# Technical synthesis

A robot operation program can be well written and still fail as part of a social technical system because moving around the environment requires considerations of people, rules, and unexpected behavior. For example, a robot could be programmed to follow a programmed path through a shared hallway while still fulfilling its speed, turning, and stopping requirements, but the path could still create problems for pedestrians or block someone with accessibility needs. A mathematically correct trajectory does not automatically mean that the robot is safe, accessible, or convenient. Additional tests would be needed, including live testing in the actual environment, observations of pedestrian interactions, accessibility considerations, and confirmation that the robot can tolerate workplace or shared-space rules. This shows why technical tests should be compared with real-world evidence when evaluating autonomous or semi-autonomous robotic systems.
